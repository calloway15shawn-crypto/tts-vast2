# Озвучка сценариев на арендованной видеокарте (Vast.ai)

Скрипт сам арендует видеокарту на Vast.ai, ставит модели озвучки, озвучивает все сценарии из папки `scripts`, проверяет каждый фрагмент распознаванием речи, перегенерирует ошибки, скачивает готовые MP3 с отчётами в папку `output` и удаляет машину.

Модели: **Qwen3-TTS** (русский, английский, немецкий, французский, испанский, португальский, итальянский) и **VoxCPM2** (польский). Проверка: **Whisper large-v3-turbo**. Все три — с открытыми лицензиями, допускающими коммерческое использование.

---

## Разовая настройка (примерно час)

### 1. Python
Скачайте Python 3.10 или новее с python.org. При установке **поставьте галочку «Add python.exe to PATH»**.

### 2. Установка скрипта
Распакуйте архив в любую папку, например `C:\tts-vast`, и дважды щёлкните **`1_install.bat`**. Появится файл `config.yaml`.

### 3. Аккаунт Vast.ai
1. Зарегистрируйтесь на vast.ai и пополните баланс (для начала хватит $5–10).
2. Откройте **Keys → +New**, скопируйте ключ (он показывается один раз).
3. Откройте `config.yaml` в Блокноте и вставьте ключ в строку `vast_api_key`.

### 4. GitHub
Машина Vast скачивает код сервера с вашего GitHub.
1. Зарегистрируйтесь на github.com и создайте репозиторий, например `tts-vast` (можно приватный).
2. Нажмите **uploading an existing file** и перетащите **содержимое** папки проекта (не саму папку): внутри репозитория должны оказаться папка `server`, файлы `run.py`, `README.md` и остальные.
   **Не загружайте `config.yaml`** — в нём ваш ключ Vast.
3. В `config.yaml` впишите `github_repo: "ВАШ_ЛОГИН/tts-vast"`.
4. Если репозиторий приватный: GitHub → Settings → Developer settings → Personal access tokens → **Fine-grained tokens** → Generate. Доступ — только к этому репозиторию, права **Contents: Read-only**. Токен вставьте в `github_token`.

### 5. Образец голоса
Положите в папку `voices` файл `narrator.wav` или `narrator.mp3`: 10–20 секунд чистой речи одного человека, без музыки и шума. Используйте только голос, на который у вас есть права: свой, нанятого диктора или купленный.

### 6. Пробный запуск (стоит несколько центов)
Дважды щёлкните **`3_test.bat`**. Модели не ставятся, вместо речи будет тон — проверяется, что Vast, GitHub и ключи настроены правильно. Если в конце появилось «Всё готово» и «Машина удалена» — всё работает.

## Обычная работа

1. Положите сценарии в папку `scripts`. Имя файла заканчивается кодом языка:
   `tema01_ru.txt`, `tema01_es.txt`, `tema01_pl.txt`.
   Коды: `ru en de fr es pt it pl`.
2. Дважды щёлкните **`2_check.bat`** — скрипт найдёт ошибки в текстах и посчитает примерную стоимость. Машина не арендуется.
3. Дважды щёлкните **`4_run.bat`** и подтвердите запуск буквой `y`.
4. Результаты — в папке `output`:
   - `tema01_ru.mp3` — готовая озвучка (48 кГц, громкость −16 LUFS);
   - `tema01_ru_отчёт.txt` — фрагменты, которые не прошли автопроверку, с таймкодами. **Слушать нужно только их.**

Уже озвученные файлы при повторном запуске пропускаются. Чтобы озвучить заново — удалите MP3 из `output` или запустите `py run.py --overwrite`.

### Требования к тексту
- **Цифры — ошибка**, запуск не начнётся: пишите числа словами в нужном падеже.
- Предупреждения (запуск не блокируют, но лучше исправить): римские цифры, латиница в русском тексте, сокращения вроде «т. е.», «г.», «до н. э.».
- Пустая строка или перенос строки — новый абзац (пауза длиннее).
- Кодировка UTF-8 (в Блокноте: «Сохранить как» → Кодировка UTF-8).

## Сколько времени и денег
- Первый запуск на новой машине: 15–25 минут на установку и скачивание моделей.
- Qwen3-TTS на RTX 4090 озвучивает примерно в 3–4 раза быстрее реального времени, плюс время на проверку. Час аудио — порядка 20–25 минут работы.
- Цена RTX 4090 на Vast обычно $0,3–0,6 в час. Точную оценку показывает `2_check.bat`.

## Если что-то пошло не так
- **Скрипт сам удаляет машину** после работы, при ошибке и при закрытии по Ctrl+C. Для спокойствия после первых запусков загляните в консоль Vast → Instances или запустите **`5_cleanup.bat`**.
- **Ошибка установки на сервере** — в папке `output` появится `логи_сервера_….txt`. Первые реальные запуски могут упасть на установке зависимостей: пришлите этот файл, по нему видно, что исправить.
- **«Нет свободных машин»** — поднимите `max_price_per_hour` или добавьте `"RTX 3090"` в `gpu.names`.
- **Много фрагментов в отчёте** — проверьте образец голоса (шум и музыка портят результат) и текст: сокращения и латиница — частая причина.

## Настройки `config.yaml`
| Параметр | Что делает |
|---|---|
| `gpu.interruptible: true` | Прерываемые машины в 2–3 раза дешевле. Если машину отключат, скрипт возьмёт другую и доозвучит оставшееся. |
| `check.max_wer` | Допустимое расхождение распознанного текста с исходным. Меньше — строже, больше перегенераций. |
| `check.clone_mode: icl` | Копировать не только тембр, но и манеру образца. Нужен файл `voices/narrator.txt` с точной расшифровкой образца. Лучше работает, когда образец на том же языке, что и сценарий. |
| `engines: {ru: voxcpm}` | Озвучить язык другой моделью, например для сравнения. |

## Как это устроено
```
run.py (ваш компьютер) ──► Vast API: аренда RTX 4090 с образом pytorch/pytorch:2.8.0-cuda12.8
                                        │
                     машина скачивает код с GitHub, запускает server/app.py (API с токеном)
                                        │
                  сервер ставит окружения: qwen (Qwen3-TTS + Whisper), voxcpm (при польском)
                                        │
        текст → фрагменты по предложениям → озвучка → Whisper распознаёт → сравнение с текстом
                     └── расхождение или странный темп → перегенерация (до 3 раз)
                                        │
                  склейка с паузами → нормализация громкости → MP3 + отчёт → ваш компьютер
```
Токен доступа к API создаётся заново при каждом запуске и живёт только на время аренды.

## Озвучка по API (вместо папки `scripts`)

Если текст приходит из вашей программы, а не из файлов, запустите **`6_api.bat`**. Это локальный сервис на вашем компьютере: принимает текст запросом, сам арендует машину, возвращает готовый MP3. Папка `scripts` при этом не нужна, `4_run.bat` продолжает работать как раньше.

Машина поднимается при первом запросе и удаляется после простоя (`api.idle_minutes`, по умолчанию 10 минут). Пока она жива, новые запросы уходят на неё же — установка моделей не повторяется. Десять запросов подряд платят за установку один раз, а не десять.

Озвучка занимает десятки минут, поэтому API асинхронный: запрос возвращает номер задачи, готовность спрашивается отдельно.

```
POST   /tts              {"text": "…", "lang": "ru"}  → 202 {"id": "…", "status": "queued"}
GET    /tts/{id}                                      → статус, стадия, сколько фрагментов готово
GET    /tts/{id}/audio                                → готовый MP3
GET    /tts/{id}/report                               → отчёт о подозрительных фрагментах
GET    /tts                                           → все задачи
DELETE /tts/{id}                                      → отменить, пока не начата
GET    /status                                        → машина, стоимость, счётчики задач
```

Необязательные поля запроса: `name` (имя файла в `output`), `voice` (другой образец из папки `voices`), `settings` (переопределяет раздел `check` из config.yaml для одной задачи).

Пример:

```python
import requests, time

base = "http://127.0.0.1:8800"
job = requests.post(f"{base}/tts", json={"text": "Летом того года…", "lang": "ru"}).json()
while requests.get(f"{base}/tts/{job['id']}").json()["status"] not in ("done", "failed"):
    time.sleep(30)
open("gotovo.mp3", "wb").write(requests.get(f"{base}/tts/{job['id']}/audio").content)
```

Текст проверяется сразу при приёме: цифры и неизвестный язык дают `400` с перечнем проблем, машина при этом не арендуется. Предупреждения (латиница, сокращения) возвращаются в поле `warnings` и запуску не мешают.

Настройки — в разделе `api` файла `config.yaml`. По умолчанию сервис слушает только `127.0.0.1` и не требует токена. Если открываете его в сеть (`host: "0.0.0.0"`), **обязательно задайте `api.token`** — иначе любой в сети сможет арендовать машины за ваши деньги; без токена сервис в этом режиме просто не запустится.

Предохранители: `max_session_hours` удаляет машину, если сессия затянулась, `max_tries` ограничивает число новых машин на одну задачу. Если сервис упадёт с арендованной машиной, удалите её через `5_cleanup.bat` — при старте сервис сам предупредит о таких машинах.
